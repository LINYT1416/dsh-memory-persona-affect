# 人格插件 · 已知问题（实测，非推测）

## K1 快拍没有真的跳过慢器官 —— 已修（2026-11-19）
- 位置：OFC（价值评估），也影响所有慢变量
- 现象：`per.tick([])`（没有任何用户事件）之后 `reads.ofc.warm` 从 0.35 涨到 0.7
- 含义：注释与文档里说的"快拍跳过没有 fast() 的器官"没生效；每来一次轮询/空拍，慢变量也在被推进
- 影响：慢层（价值/自我/叙事）会被聊天频率污染——问得勤，她就"变"得快，跟人的时间尺度不符
- 证据：tests/persona-ofc-warm.mjs 里原来的断言（role:user 写法下恒 0）掩盖了这件事

### 修法与验证
- engine.js：`const fastBeat = !Array.isArray(events) || events.length === 0`，快拍只跑 ORDER_A（习惯层），ORDER_B（价值/自我/叙事/读人）不推进
- 注意不能用去重后的 uniq 判断：重复同一句话会被 30 秒去重成空，但那仍是真回合
- 验证：`per.tick([])` 后 ofc.warm 不再变化（persona-ofc-warm 绿）；selftest 34 项全过

## K3 口吻语料被技术汇报污染（2026-11-19 发现）
- 现象：她最近 45 分钟记下的 28 条「我说」里，句均 **68.4 字**、语气词 0.11/条
- 原因：那些其实是我写的插件汇报（带代码块、标题、表格），被记忆当成「她说过的话」
- 后果：口吻统计 → 偏置 → 她越说越长（自己喂自己）
- 修法：进语料前过滤掉 ```、##、| 以及超长（>80 字）的条目；不足 5 条时退回自述

## K5 为了让注入"满"而放宽阈值 → 平常状态被说成异常（2026-11-19，已回退）
- 想解决：真实对话 10 句后，37 条规则只触发 3 条，注入只有 2~4 行
- 试法：加"临界档"，读数到阈值 72% 就用 light 说法（同一段对话立刻从 2 行变 8 行）
- 三个测试同时红，其中最要命的一条：`esteem=0.5` 是默认值，却恰好是 lowEsteem 阈值的 83%
  → 什么都没发生，注入里就冒出「有点怀疑自己」
- 处理：整段回退（selection 恢复 ratio>=1），删掉对应的 near-miss 测试文件，不留半成品
- 正确做法：判断"偏离默认值多少"（`v - 默认`），不是 `v / 阈值`
- 顺手修了根源：`mask/unmask` 原来用 `presentation` 绝对值，默认 0.5 就有 0.81 的占比；
  改成 `presentation - 0.5` / `0.5 - presentation` 后，默认值为 0，永不误报
- 现在的守卫：有脚本逐条算 `v(默认)/at`，>0.6 就报出来（当前 0 条）
- 教训：「让输出变多」不能靠降低门槛，只能靠让状态真的偏离

## K6 两条规则"每句都在说"——真因是器官读数恒为极值（2026-11-19，已修）
- 做法：新写了 `tools/rule-audit.mjs`，喂 30 句情绪跨度很大的对话，统计每条规则触发次数
- 结果：`empathyHigh` 30/30、`noFuture` 30/30 —— 每一句都在说「我懂他」「后面一片糊」
- 根因一：`tpj` 的 else 分支把「读不准（unclear）」也算成 `correct += 1`，于是 `empathy = correct/reads` 恒等于 1
  - 修：三分支——读错记 misread，读明白记 correct，读不准两边都不记；精度 = correct/(correct+misread)，无证据给 0.5
  - 结果：empathy 不再是常数，但**仍然偏向 1**（因为只要做出有把握的判断就记对，没有反馈能证伪）
  - 结论：这个读数目前**表达不了"我读懂了没有"**，所以撤掉 `empathyHigh` 这条规则——说了就是假阳性（宁可漏）
- 根因二：`noFuture = 1 - pcc.future`，而 `future` 冷启动就是 0（要有 4 个锚点才涨）→ 开局就说「后面一片糊」
  - 修：`anchorCount > 0` 才允许判断
- 复跑：`empathyHigh`、`noFuture` 都不再出现在"每句都说"的名单里；规则数 41 → 40
- 教训：**"接上了"不等于"在说话"，"一直在说话"更不等于"说得对"**——要按触发频率审，不只看引用

## K7 大部分器官读数常年为 0，是因为特征词表太窄（2026-11-19，部分修）
- 现象：40 条规则里 28 条在 30 句对话中一次都没触发；逐条打印读数，发现 `offense / error / misread / deception / error` 等 **恒等于 0.000**
- 根因：`core/consts.js` 的 `features()` 只认一批固定词。实测：
  - 「闭嘴」「别烦我」「你行不行啊」→ 既不算 cold 也不算 command → `offense` 恒 0
  - 「加班到十点，好累」→ 不在 complaint 里 → 不会进入"累"的分支
  - 「谢谢你陪我聊」→ warm 命中「谢」，但 favors 只涨 0.2，进不了阈值
- 本轮的修（保守，只补词不改编排）：
  - `cold` 加：闭嘴 / 别烦 / 不想聊 / 一边去 / 爱咋咋
  - `complaint` 加：好累 / 好烦 / 加班 / 顶不住 / 熬不住 / 撑不住
  - `warm` 加：辛苦 / 麻烦你 / 多谢
- 验证（单句探针）：`闭嘴 → offense 0.275`、`别烦我 → offense 0.475`、`谢谢你陪我聊 → warm 0.35`
- 复跑审计：30 句里触发过的规则 10 → 12；仍有 28 条不触发
- 结论：**症状缓解，病根还在**——器官要靠词表驱动，真实说话会大量漏判。下一步要么继续按真实语料补词，要么把"读人"从词表换成更稳的特征
- 这条不宣称"修好"，只记录修到哪一步

## K9 注入里有两套名额，别混着算（2026-11-19）
- 现象：`speechBudget` 把上限压到 5，但实测注入仍有 9~14 行
- 原因：预算管的是**读数转句**（`describe()` 的 `max`）；而关系账本、目标、自我效能、读空气、发言决策这些**行为句**是另外 push 的，各自有自己的 `want + n` 上限
- 为什么要分开：读数句是"她现在什么状态"，行为句是"这一条该怎么做"。状态可以少说，但"该收着"这种事不能因为名额不够就不说
- 证据：`tools/inject-sanity.mjs` 跑 8 轮，注入 9~14 行，指令 0~1 条，无互相矛盾
- 风险：行为句多起来会稀释注意力。现在最多 5 类（关系/目标/效能/空气/发言），任意一拍同时出现超过 2 条会被 `inject-sanity` 判失败
- 结论：**不要用"注入行数"当预算是否生效的判据**，那会误判

## 2026-11-19 插件把 DSH 整个带走（qq-direct）

现象：装完 qq-direct 重启，DSH 自己退出。

根因：轮询函数只有 try/finally、没有 catch，且被 setInterval 和启动调用直接调用，都没接 Promise。
SnowLuma 重启期间 3000 断着，fetch 抛错 → 未处理 rejection → 宿主进程退出。
「拉活」里 ctx.agents.get 也写在 try 外面，服务自己抛时同样会漏。

规矩（以后每个插件都照做）：
1. 每个异步入口自己 catch：setInterval 回调、启动时调的函数、事件里的 async 回调。
2. ctx.xxx 的调用也放进 try。
3. 改完跑一遍「服务断掉」的场景（fetch 换成 reject），确认进程还活着。
4. catch 里至少记一行日志。

详细记录：packages\qq-direct\MISTAKES.md
